# Beep Source

Небольшое нативное приложение для macOS: локальная история звука с указанием приложения/процесса, времени, длительности и пикового уровня. Версия 1.0, 9 октября 2026.

## Как пользоваться

1. Откройте **Applications → Beep Source**. Наблюдение начинается при запуске.
2. При первом запуске разрешите доступ к системному аудио. Если событий нет: **Настройки системы → Конфиденциальность и безопасность → Запись экрана и системного аудио**; разрешите Beep Source, затем в меню приложения выберите «Перезапустить наблюдение».
3. Закройте окно — приложение останется в строке меню со значком волны. Нажмите значок, чтобы открыть историю; правый клик открывает меню паузы и выхода.
4. После непонятного сигнала нажмите **«Только что слышал звук»**: покажутся события начиная с 30 секунд до нажатия, а также последующие. **«Вся история»** снимает этот фильтр. **«Короткие · до 3 с»** помогает убрать длительную музыку.
5. Щёлкните строку, чтобы увидеть точное время, PID, Bundle ID и путь приложения. Поиск работает по этим данным.
6. Меню **…** содержит автозапуск при входе, перезапуск наблюдения, экспорт CSV, очистку с подтверждением и выход. Автозапуск изначально выключен.

История: `~/Library/Application Support/Beep Source/history.json`. Хранятся последние 30 дней, максимум 5 000 событий. Аудиозаписи не создаются; сетевых функций и сторонних зависимостей нет. Во время работы история сохраняется раз в 3 секунды и при штатном выходе. Неожиданное завершение может потерять последние несколько секунд.

В первоначальном журнале остаются тестовые сигналы от `afplay`, использованные для проверки приложения. Не путайте их с искомым сигналом.

## Что означают данные

- Событие подтверждается ненулевым PCM-сигналом выше **−65 dBFS**, а не только открытым аудиоканалом.
- Начало/конец определяются по первой/последней выборке выше порога. Пауза меньше **220 мс** объединяет соседние фрагменты. Подтверждение тишины занимает примерно 220–400 мс, но не прибавляется к длительности.
- Пик в dBFS — уровень цифрового сигнала. Он не измеряет физическую громкость динамиков и не гарантирует, что звук был слышен при системном отключении звука.
- Имя приложения для helper-процесса выводится по enclosing `.app`; исходное имя процесса и PID сохраняются отдельно. Вкладки/сайты браузера не определяются.
- Системный процесс может играть уведомление по просьбе другого приложения. В таком случае инициатор уведомления может быть неизвестен.
- Для нового процесса возможен звук до создания индивидуального tap. Общий резервный tap сохраняет такой сигнал как **«Источник не определён»**, если он не совпадает с уже атрибутированным событием. При одновременной музыке неизвестный сигнал может остаться незаметным.
- Доступ к аудио/драйверы/защищённое содержимое могут ограничивать видимость. Отсутствие сигнала нельзя надёжно отличить от отсутствия разрешения по нулевым PCM-буферам. Статус «Ожидаю звук» не обещает выданное разрешение.

## Требования и сборка

Готовая сборка рассчитана на **Apple Silicon**, macOS **14.2+**. Проверена на macOS 26.5. Для сборки нужны Xcode/Command Line Tools с современным SDK. Используется Swift 5 language mode с компилятором Swift 6.3.3, AppKit/SwiftUI, CoreAudio и ServiceManagement.

```sh
cd /path/to/BeepSource
./test.sh
./build.sh
```

По умолчанию `build.sh` создаёт `.build/Beep Source.app`, промежуточные файлы тоже находятся в `.build` внутри репозитория. Можно задать `BS_BUILD_DIR`, `BS_APP_PATH`, `BS_SIGN_IDENTITY`. Для сборки без сертификата автора: `BS_SIGN_IDENTITY=- ./build.sh` (ad-hoc подпись, без timestamp/hardened runtime). Для публичного релиза обязательно использовать Developer ID. Перед заменой установленной сборки штатно выйдите из приложения.

```sh
ditto '.build/Beep Source.app' '/Applications/Beep Source.app'
codesign --verify --strict --verbose=2 '/Applications/Beep Source.app'
open '/Applications/Beep Source.app'
```

Подпись: **Developer ID Application: Gennadiy Zakharov (BN3D9H4C7J)**, сертификат SHA-1 `6E99F92E9A1BA1273CD084FAFE940A7280DB0A30`, issuer **Developer ID Certification Authority / G2**. Hardened Runtime и Apple timestamp включены. Приватный ключ остаётся в системной связке ключей; в исходниках его нет. Публичный релиз 1.0.0 успешно нотарифицирован Apple (submission `8541794c-f293-441c-a8eb-3f8d6ad9ef77`, статус Accepted); ticket прикреплён к .app. Проверены stapler validate, codesign и Gatekeeper. ## Карта исходников

- `AudioMeter.m/.h`: private stereo process tap и private aggregate без аппаратных outputs; `CATapUnmuted`, tap auto-start. C IO callback считает peak/first/last samples и пишет в lock-free SPSC ring, без логов, диска, allocation, ObjC/Swift вызовов. Нулевой process ID — общий резервный tap.
- `Events.swift`: Codable-модели и чистая логика объединения событий/завершения по тишине.
- `Engine.swift`: serial utility queue, HAL process-list listener плюс сверка раз в 3 секунды; метаданные процесса; дренирование раз в 180 мс; перезапуск при смене default обычного/системного output; backoff ошибок. Каждый process tap создаётся заранее, включая пока молчащие процессы. Общий tap создаётся первым; резервные события ждут 600 мс и подавляются при пересечении с известными. Стоп IO происходит до финального дренирования.
- `Store.swift`: main-thread observable state, атомарная JSON-запись на отдельной очереди, retention, CSV, login item, sleep/wake. Повреждённая история сохраняется отдельно; если сохранить резервную копию не удалось, запись отключается.
- `Interface.swift`: русскоязычное окно, поиск, фильтры, детали и меню.
- `App.swift`: жизненный цикл NSApplication, NSStatusItem, окно, штатное завершение с сохранением. Закрытие окна не завершает приложение. `--background` скрывает окно при запуске; login launch распознаётся по AppleEvent.
- `Tools/Icon.swift`: генерирует нативную векторную иконку с waveform и PNG/iconset для `iconutil`.

## Проверено

- `test.sh`: короткий щелчок, завершение по тишине без хвоста, объединение/разделение соседних звуков, пик, сохранение идентификатора процесса, JSON round-trip.
- Реальный звук через `afplay`: Ping **269 мс**; два одновременно работающих PID и отдельные сигналы **79, 159, 239 мс**. Стереоканалы тестовых WAV были в противофазе: измерение по stereo сохранило сигналы. Резервный tap не добавил дубли.
- Поиск/фильтр и пауза через UI, сохранение и восстановление пяти событий после штатного выхода/запуска.
- С закрытым окном процесс остался запущен и записал ещё два тестовых сигнала (79 и 239 мс); история выросла с пяти до семи событий.
- Подпись установленного bundle проверена `codesign --verify --strict`.
- В тишине с 32 HAL-процессами: **0,0–0,3% CPU** приложения в нескольких замерах `top`, около **31 MB** в его колонке MEM. Пиковая нагрузка при старте выше; фактическое потребление зависит от процессов/драйверов/аудио.

Не проверялся реальный повторный вход в macOS, sleep/wake и переключение Bluetooth/HDMI (обработчики реализованы, но эти действия не выполнялись на рабочем Mac пользователя). При дальнейших изменениях аудиодвижка повторить реальный многопроцессный тест. Не подменять PCM detection на `kAudioProcessPropertyIsRunningOutput`: это создаёт ложные события от молчащих каналов.
